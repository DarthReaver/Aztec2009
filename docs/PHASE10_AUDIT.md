# Phase 10 audit: lighting, rendering, render layers and passes (Lessons 20, 21 and 28)

## Coverage
| Lesson topic | Status |
|---|---|
| References for the set (Lesson 20 start) | Existing (Phase 8 references) |
| Point, directional, ambient lights; hardware lighting in the views | Lights existed. **New**: Lighting > Use All Lights / Use Default Lighting in the view panel menu (`Scene::use_all_lights`) |
| Shadows (Use Depth Map Shadows, resolution, filter size) | Light channels `useDepthMapShadows`, `dmapResolution`, `dmapFilterSize`. **Shadows are ray traced, not depth maps**: a lower resolution or a larger filter only widens the blur of the shadow edge. Per-object Render Stats: `castsShadows`, `receiveShadows`, `motionBlur`, `primaryVisibility`, `visibleInReflections` (`renderStats`, Attribute Editor > Render Stats) |
| Light linking | `lightLink LIGHT obj...`, `-break`, `-q`: a linked light illuminates only its objects |
| Light fog, light glow, lens flare (opticalFX) | Light channels `fogType/fogRadius/fogIntensity`, `lightGlow/glowType/glowIntensity/glowSpread`, `haloType/haloIntensity`, `lensFlare/flareIntensity` (Attribute Editor > Light Effects). Fog is a sphere (cone for spots) around the light, scaled by the light's transform, not shadowed. The glow is hidden when a surface is in front of the light. Flare is a ring plus ghosts, not Maya's full flare model |
| Render Settings: renderer, quality, resolution, file name prefix, image format, frame range, by frame, frame padding, alpha/depth channel, renderable cameras | Done: `renderSettings` (also channels of `defaultRenderGlobals`) and the Render Settings window (Common, Quality, Motion Blur, Vector, Passes). Formats: png, jpg, bmp, tga (**no IFF, EXR or tif**). Resolution gate: Lighting menu / Common tab |
| Motion blur 2D and 3D, blur length, per-object motion blur | Done. 2D smears the finished picture along each pixel's screen movement (from the object's position one frame earlier, so deformation without object motion is not blurred); 3D renders `blurSamples` moments of the shutter and averages them. Objects with Motion Blur off stay at their position |
| Batch Render, Cancel Batch Render, command line render, Show Batch Render, FCheck | `batchRender` (all frames, renderable layers and passes into `images/`), `aztec2009 --render -s 1 -e 10 -rl LAYER -cam C scene.aztec`; the window runs the batch in a separate process you can cancel; FCheck window (Open Sequence, Play, slider) and `fcheck` with `-contact` sheets. FCheck keeps frames on disk (no cache in memory) |
| Render View: keep and remove images, region render, snapshot, open and save image, alpha display, IPR | Done in the Render View when "Render Settings" is the renderer. **IPR** renders the tuned region again after every command (a full region render, not Maya's incremental IPR file); clicking the picture in IPR mode selects the object's material |
| Render using Maya Software, Maya Hardware, Maya Vector, mental ray | **Software** = ray tracer. **Hardware** = no ray tracing, fewer shadow rays (not a GPU renderer). **Vector** = flat fills (single, full, two color) and outlines, written as a bitmap (no SVG or SWF). **mental ray is out of scope** |
| Rendering considerations: tessellation, frame range, renderable camera, masks and depth masks, resolution, raytracing, quality presets | Frame range, renderable cameras (`renderable` channel, persp by default), alpha and depth, resolution, raytracing flag and quality presets exist. Per-surface tessellation is not exposed (NURBS surfaces use their display tessellation) |
| Render layers: create, add objects and lights, renderable flag, per-layer Render Settings with layer overrides, tokens in the file name prefix | Done: `renderLayer`, `renderSettings -layer L` (an override), Render Layers window. A layer renders only its objects and lights (no lights: default lighting). Tokens `<Scene>`, `<RenderLayer>`, `<Camera>`, `<RenderPass>` |
| Render passes | Per layer: `diffuse`, `specular`, `shadow`, `reflection`, `color`, `depth`, `normal`, `mask`, `motion` (screen motion vectors in two 8 bit channels), plus beauty. Written as PNG: **no 32 bit EXR** for true motion vector data, no mental ray pass contribution maps, no occlusion pass |
| Surface shaders for compositing, Toxik | Surface shaders exist; Toxik is out of scope |

## Effects on the program
* New node `renderGlobals` (`defaultRenderGlobals`), made by new scenes. Camera shapes get `renderable`; mesh shapes get the Render Stats channels; lights get the shadow map and Light Effects channels. Render layers (`renderLayer` lines) and light links (`lightLink` lines) are saved at the end of the scene file.
* `render::raytrace` now returns buffers (color, alpha, depth, surface, position, normal) and understands passes, region rendering, render stats and light linking. `render::pipeline` holds the settings, layers, passes, motion blur, light effects, vector style and file naming.
* New commands: renderSettings, renderImage, batchRender, renderLayer, lightLink, renderStats, fcheck. The old `render` (ASCII passes), `rayRender` and `playblast` still work as before.

## Tests
`phase10_render_settings_batch_and_fcheck`, `phase10_lights_shadows_links_and_effects`, `phase10_motion_blur_passes_layers_and_renderers` render small pictures and check them (shadow areas with and without Render Stats, soft depth map edges, light linking, glow, fog, flare, 2D and 3D blur, passes, layers with overrides and tokens, renderers, region render, file names, save and load). 174 tests pass in all. The new windows (Render Settings, Render Layers, FCheck, Render View additions, background render and batch processes) are compiled and smoke started, not clicked through.
